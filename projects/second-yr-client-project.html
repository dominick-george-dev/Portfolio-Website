NHS Wales Recruitment App

An internal applicant-tracking web app for NHS Wales recruiters to search, review and contact candidates. Built with Spring Boot in an Agile team, working directly with the client.

  • Spring Boot
  • Spring Security
  • Thymeleaf

Overview

Recruiters needed one place to manage applicants. Staff sign in, search and filter the candidate database, open a profile for each candidate, shortlist favourites, email candidates in bulk and see which recruitment events are bringing people in.

My role & team

I worked in a five-person Agile team: we planned sprints, met the client regularly to demo progress and gather feedback, and presented the finished product to them. I used the project to deliberately build experience in three areas beyond feature work: security, DevOps and performance & scalability.

Key features

  • Sign-in with a self-service password reset by emailed, time-limited link.
  • Searchable, filterable candidate table.
  • Candidate profiles with qualifications, skills, CV upload and a countdown to each record's expiry date.
  • Bulk email to selected candidates through Spring Mail.
  • Statistics page showing which events (careers fairs, open days) candidates came from.
  • Admin area for managing the app.

Security

  • Authentication on every route. Spring Security form login; everything except the login and password-reset pages and static assets requires a signed-in user.
  • Hashed passwords. Stored with BCrypt. Users and their authorities (roles) are loaded from the database, and access-denied requests go to a dedicated 403 page.
  • CSRF protection left on (Spring Security's default) for every form.
  • Safe password resets. Reset tokens are hashed with BCrypt before they're stored, carry an expiry time, and a scheduled job deletes expired tokens every five minutes.
  • Tested. Controller, service and repository tests for candidates, email and statistics, run with Spring Boot Test and Spring Security Test.

What I'd improve next

  • Uploaded CVs are currently served from whitelisted paths, so they're reachable without signing in. They should sit behind authentication with a role check, since they contain personal data.
  • Run the test suite plus dependency and static security scanning in CI on every merge request.
